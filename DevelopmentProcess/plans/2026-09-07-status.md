## Визия

"Node diagram = application". Два режима:

- **Editor режим** (текущ): node editor, редактиране, дебъгване
- **Runtime режим**: `Daqster --run <flow.flow>` — editor-ът е скрит,
  деембеднатите виджети на нодовете формират UI-то на приложението

Деембедингът е ключовият механизъм — мостът между editor и приложение
(LabVIEW front panel / Pure Data presentation mode / TouchDesigner perform mode).

## SDRangel проучване (уроци)

- Workspace = QDockWidget обвиващ QMdiArea; plugin GUIs = QMdiSubWindow
- Configuration persistence: версионирани per-widget blobs; settings отделно от geometry
- Custom geometry blob {x,y,w,h,maximized} — QWidget::saveGeometry е ненадежден за MDI
- Core/GUI split: същият PluginInterface, GUI factory-тата връщат nullptr headless; два бинарника
- Message/MessageQueue за между-нишкова комуникация
- ДА НЕ копираме: бинарни blobs, FSM sprawl, singleton MainWindow, magic-number geometry fixes, QSettings като единствен storage

## Одит на текущото състояние (8 празнини)

1. няма --run CLI флаг (само DAQSTER_AUTOSTART_FLOW env)
2. деембедната геометрия не се персистира
3. няма unified stop()/wait() на NodeDelegateModel
4. .flow няма runtime metadata (ui секция)
5. няма editor hiding / presentation toggle
6. auto-start е video-specific (startVideoPlayback)
7. WindowStaysOnTopHint без window management
8. async shutdown (deleteLater верига) — нишките може да работят при exit
