## Diagnosis: Qt6 green screen = Qt FFmpeg-backend VC-1 decode bug (NOT our code)

- Test file `50MB_1080P_THETESTDATA.COM_AVI.avi`: codec VC-1 Advanced profile,
  container ASF (mislabelled .avi), yuv420p 8-bit, 1920x1080@60.
- Evidence chain (standalone probe using the same QMediaPlayer+QVideoSink
  pattern as VideoCompat, no Daqster presentation code):
  1. System FFmpeg CLI decodes file correctly (real content).
  2. Qt-bundled libavcodec 61 (FFmpeg 7.1) driven directly: real content,
     0/30 zero-chroma frames.
  3. H.264 via Qt6 backend: real content (pipeline proven sound).
  4. VC-1 remuxed to MKV via Qt6: same zero-chroma garbage (not container issue).
  5. VC-1 via Qt6 QFFmpegMediaPlugin: NV12 frames with ENTIRE chroma plane zero
     (Cb=Cr=0) → YCbCr→RGB = solid green (0,226,0). Both display paths (GPU
     QVideoWidget + software QLabel) show green because both consume the same
     garbage frames.
- Confirmed codec difference: `clipGolemDelivers.avi` (Cinepak rgb24) plays
  fine on Qt6. H.264 also fine.
- Qt5 works for VC-1 because it uses GStreamer backend.
- CONCLUSION: upstream Qt 6.9.2 bug in QFFmpegMediaPlugin for VC-1 Advanced
  content. Not fixable in Daqster code. Not a regression from recent
  optimizations (zero-chroma produced inside Qt's decoder; standalone probe
  reproduces it without any Daqster presentation code; PL-020 was verified only
  as "compiles + no crash" — pixels never checked).
- Known-issue note for changelog: "VC-1 Advanced content shows green screen on
  Qt6 (Qt FFmpeg backend zero-chroma decode bug; works on Qt5 via GStreamer).
  H.264/Cinepak work."

## Fix: popup closes on input disconnect (VERIFIED by user)

- Branch `fix/video-popup-close-and-qt6-green`, commit `d86b095`.
- Root cause: disconnecting the edge does NOT stop the source player — frames
  keep flowing into `setInData()` and lazily re-create the detached
  `QVideoWidget` (`ensureVideoWidget()`). Also `inputConnectionDeleted()` was
  never implemented.
- Fix: `m_videoInputConnected` flag via `inputConnectionCreated`/`Deleted`
  overrides; guard `setInData()` port-0 branch with it; on disconnect hide +
  deleteLater + nullptr the widget, reset state, restore QLabel placeholder.
  Defensive null-check before `presentFrame()`. Also stops emitting `ImageData`
  wrapping null `QImage`.
- Qt5 unaffected (`#if QT_VERSION >= 6`). Compiles on Qt5 + Qt6; ctest 5/5;
  nodes tests 11/11.
- User manually verified: disconnect now hides the window. ✔
