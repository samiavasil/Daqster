## Bug fix: VideoOutputNode per-frame QImage conversion on GPU path

### Root cause
`VideoOutputNode::setInData()` port 0 (Qt6, video-frame input) unconditionally
called `VideoCompat::frameToImage()` + `updateDisplay()` + created `ImageData`
on every frame, even when the GPU path (detached `QVideoWidget` via
`presentFrame()`) was already handling display. This doubled CPU work — the user
observed two displays and high CPU.

### Fix (commit `2bf9b39`)
- **VideoOutputNode.h**: Added `outputConnectionCreated`/`outputConnectionDeleted`
  override declarations (public, matching source-node pattern) and
  `m_outputConnectionCount` member (int, default 0, Qt6-gated).
- **VideoOutputNode.cpp**:
  - Implemented `outputConnectionCreated`/`outputConnectionDeleted` — track
    connections on output port 0 (`conId.outPortIndex == 0`), Qt6-gated.
  - In `setInData` port 0: gated the per-frame `frameToImage()` +
    `updateDisplay()` + `ImageData` output behind `m_outputConnectionCount > 0`.
    The GPU path (`presentFrame()` + `ensureVideoWidget()`) is unchanged.
  - In `ensureVideoWidget()`: set the in-node QLabel to a static placeholder
    ("GPU display active — see detached window") once, instead of updating it
    per-frame.
- Qt5 path unchanged (no GPU path; always does QImage conversion).
